# Phase B performance baseline — 2026-10-28

`bun scripts/bench-run-loop.ts` (Bun 1.4.0, Apple M-series, macOS arm64).
NOT a CI gate — no absolute budget; the rule is "no regression vs the same
machine". Baseline = `a8629bd` (last reviewed master) run in a clean worktree
with the same script and same bun; current = Phase B tip (`9c1116a`).

Shapes (a)–(c) are the frozen M0/M1 shapes from `m0-2026-10-27.md`.
(d)–(f) are new in Phase B and measure the cost of the new opt-in seams:
(d) `@agentkit/cassette` in OFF mode wrapping the provider client,
(e) the B3 model-router seam with a sticky (no-switch) router,
(f) loop-side time-to-first-event in front of the provider's first frame.

Each shape: 20 warmup + 200 timed runs, p50/p95 ms over the timed samples,
RSS delta across the timed block. Baseline and current each run twice;
ranges below are min–max across the repeats.

| Shape | Baseline p50 | Current p50 | Baseline p95 | Current p95 |
| --- | --- | --- | --- | --- |
| (a) text-only, 1k-message history | 0.015 | 0.014–0.015 | 0.032–0.039 | 0.024–0.025 |
| (b) 10 tool calls (10×1) | 0.054–0.056 | 0.055–0.057 | 0.081 | 0.075–0.084 |
| (c) 100 tool calls (10×10) | 0.276–0.277 | 0.269–0.282 | 0.361–0.421 | 0.362–0.371 |

New seams (current tree only), against (b) = 0.055–0.057 / 0.075–0.084:

| Shape | p50 | p95 | Delta vs (b) |
| --- | --- | --- | --- |
| (d) cassette OFF wrapper | 0.060–0.062 | 0.082–0.091 | ≈ +0.006 ms per run (~11%) |
| (e) sticky model router | 0.060–0.061 | 0.078–0.084 | ≈ +0.005 ms per run (~10%) |
| (f) time-to-first-event (1k history) | 0.005 | 0.006–0.007 | loop-side latency before the first provider frame |

Interpretation, honestly bounded:

- (a)/(b)/(c): current lands inside the baseline's run-to-run noise on every
  repeat. Phase B (routing seam, usage stamps, accounting imports) added no
  measurable loop regression. No improvement is claimed either — p50 deltas
  below ~0.005 ms are noise on this machine.
- (d): a disabled cassette costs one wrapper delegation per provider call —
  ~0.6 µs/iteration here. Recording/replay costs are out of scope for the
  OFF path and are exercised by the cassette test suites instead.
- (e): the router seam with a no-op selection is the same order as (d). A run
  with no `modelRouter` skips the branch entirely (shape (b) measures that).
- (f): request assembly over 1,000 messages puts ~5 µs between generator
  start and the first event; unchanged in character from M0.
- RSS deltas in both trees swing with Bun's GC between repeats
  (3–23 MB observed); neither run showed growth across repeats, which is the
  leak signal this bench actually watches.

Caveat: single machine, single bun version, mock provider (zero network).
Comparisons are valid only within this table.

## Final qualification — C-phase tip

Re-run of the same script after the C phases (cassette security hardening,
`(callId, attempt)` usage re-stamping in `model-step`, router authorize gate,
host routing wiring): two repeats, current tree.

| Shape | p50 | p95 | vs baseline range |
| --- | --- | --- | --- |
| (a) text-only, 1k-message history | 0.013–0.014 | 0.022–0.024 | inside |
| (b) 10 tool calls (10×1) | 0.055–0.058 | 0.077–0.079 | inside |
| (c) 100 tool calls (10×10) | 0.280–0.285 | 0.354–0.368 | inside |
| (d) cassette OFF wrapper | 0.060–0.061 | 0.078–0.082 | unchanged vs Phase B |
| (e) sticky model router | 0.060–0.061 | 0.074–0.075 | unchanged vs Phase B |
| (f) time-to-first-event (1k history) | 0.005 | 0.007 | unchanged |

The C-phase hot-path additions — per-step usage re-stamp (one object spread
per forwarded `run.usage`), the router authorize check (only on switches),
and the cassette capture-aware view build (only in replay/verify) — are
invisible inside baseline noise on every shape. No improvement is claimed;
none was expected. RSS deltas stay in the same GC-driven 4–24 MB band with
no cross-repeat growth.
