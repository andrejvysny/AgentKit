# H0.2 Known-failures list and gate (AgentKit)

Hardening plan, package H0.2. "Done when": the script fails on any failure outside the list.

## What changed

- `scripts/known-failures.json`: every test that fails today, by name, each with a reason. 1 Rust entry (intermittent) and 11 Bun entries.
- `scripts/known-failures.mjs`: parses `cargo test` and `bun test` output and compares it with the list. A failure not on the list fails the step. A listed test that passes again fails the step as stale, so the list can only shrink; entries marked `intermittent` are exempt from the stale check. A failed target with no named test (compile error, crash, load error, or a test that cannot be tied to its binary) always fails the step.
- `scripts/gates.mjs`: the Rust `test` step and the Bun `clientreact` and `native` steps are audited against the list. A new `buntest` step runs the whole Bun suite. Each step's stdout and stderr now share one file descriptor, so the log keeps cargo's `Running <binary>` lines next to the results.
- `rust/crates/runtime/Cargo.toml`: `[[example]] context_capture` with `test = true`, so the example's context-evaluation tests run under `cargo test`. Before this change no gate ran them, which is how two failures went unnoticed (review finding, FINDINGS F6a).
- The two failing example tests, changed with the owner's approval of 17 Nov:
  - `context_eval::replay_tests::immutable_corpus_reassembles_ten_scripted_sessions` is removed. It replayed the frozen 0.4 baseline corpus (recorded at `38eacd71`) through today's runtime. Context packages 1.x and 2.x changed the request layout on purpose, so it failed with `request 0 differs` and could never pass without rewriting the baseline evidence. The corpus is unchanged.
  - The `extra_read` assertion is removed from `context_eval::tests::capture_reaches_mutation_and_report_retains_failures`. The same check exists in `agentkit-eval` as `a_restaged_tool_is_offered_after_its_contributor_turns_on`, ignored as a known bug that H2.1 owns; H2.1 must un-ignore it. The test's other assertions still run.

## Follow-up commit

A review of the first H0.2 commit (`f9ae126d`) found two problems, fixed in a second H0.2 commit:

- **The Bun stale check could not fire.** Bun prints a file header only for files that contain a failure (the full-suite log has 5 headers and no `(pass)` lines for 1,368 tests). Scope was taken from the printed headers, so a listed test whose file now passes completely was never called stale. Scope now comes from the paths each step passes to `bun test` (`bunScope`); `buntest` runs the whole suite, so every entry is in scope there. New test: `a listed Bun test in a file that now passes completely is stale`. The saved full-suite log still yields 0 problems, and `node scripts/gates.mjs --only=clientreact` passes.
- **The interrupt test is likely a race, not load.** Run alone 20 times on 17 Nov at a load average of about 3.9, `a_mid_run_interrupt_parks_and_the_resumed_turn_finishes_without_replay` passed 15 and failed 5, always the same way: the tool body never starts. It stays listed as intermittent, because it fails today, and its reason now records this. It covers park and resume in `agentkit-chat`, which H1.1 changes, so it is to be investigated with H1.1.

Proposed rule for pruning intermittent entries, for the owner to decide: on a quiet machine, run the gate twice, then remove any intermittent entry that passed both times.
