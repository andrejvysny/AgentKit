# H1.2 Request limit (AgentKit)

Hardening plan, package H1.2, blocker B2, decision D3 ("Chat request limit: 24, with a visible 'stopped after 24 steps' message and a way to continue"). OneMind side: `docs/evidence/hardening/H1.2.md` in OneMind.

## Finding

Reproduced. `ChatExecutorOptions::default()` set `max_tool_iterations: 4` (`rust/crates/chat/src/chat/hooks.rs`), and a session profile's limit can only lower it (`chat.rs`, `options.max_tool_iterations.min(limit)`). So a chat turn on default options stopped after four model requests, and so did every session whose profile asked for more.

The live OpenAI qualification run of 17 Nov shows the effect: in `acceptance-runs/2026-11-17T222021Z/agentkit/qualification/*-responses`, the failing scenarios for `gpt-6-luna` and `gpt-6.1-terra` stop at exactly 4 calls with "turn did not settle with a final answer". The qualification profile asks for `maxToolIterations: 12` (`crates/runtime/tests/qualification/mod.rs`), which the default of 4 overrode.

## What changed

- `rust/crates/chat/src/chat/hooks.rs`: the default is a private `CHAT_REQUEST_LIMIT` of 24. Session profiles still lower it. The core loop (`crates/core/src/run.rs`) is unchanged: at the limit it emits the `max_iterations` warning and `run.completed` with `finishReason: "max_iterations"` and `iterations`, which the host turns into the visible message.
- `rust/crates/chat/tests/chat_request_limit.rs` (new).
