# H1.3 Cache directives (AgentKit)

Hardening plan, package H1.3, blocker B3. OneMind side: `docs/evidence/hardening/H1.3.md` in OneMind.

The plan scoped H1.3 to OneMind ("wire cache capability into every provider path"). Checking the code showed that wiring alone would not reach OneMind's Chat, so this AgentKit change is part of the package.

## Finding

`ChatExecutor` planned cache directives only for session turns (`rust/crates/chat/src/chat.rs`). It read the chat's frozen session prefix, and a plain chat has none, so a plain chat got no `ChatRequest.cache` whatever its provider declared. OneMind's Chat is a plain chat. So even with the capability wired, OneMind would have sent no `prompt_cache_key` and no Anthropic breakpoints beyond the lane's own single system marker.

## What changed

- `rust/crates/chat/src/chat.rs` and `rust/crates/chat/src/chat/prefix.rs` (`for_cache`, moved there to keep `chat.rs` under the 1,000-line arch limit R12): a plain-chat turn whose provider declares a capability (anything but `CacheCapability::None`) now plans directives too. Its prefix is derived the way a session's first revision is: `PrefixDigests::compute` over this turn's layout, tools and model, then `freeze(None, …)`. That gives the cache key `cache_key(chat, branch, 1)`, stable across the chat's turns on one branch. Nothing is persisted. A provider with no capability still gets no directives. Session turns are unchanged.
- `rust/crates/chat/tests/chat_cache_plan.rs` (new).
