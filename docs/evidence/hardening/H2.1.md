# H2.1 Late tools announced (AgentKit)

Hardening plan, package H2.1 (context). "Announce late tools in the turn context; keep meta-tools whenever a late tool can exist. Stop dropping tool definitions per turn in OneMind; refuse at call time." OneMind side: `docs/evidence/hardening/H2.1.md` in OneMind.

## Findings (both marked "Reported" in the review)

1. **A tool that appears mid-session can be unreachable and is never announced.** Partly reproduced.
   - The announcement gap is real. `TurnNoteKind::ToolNamespaceAdded` existed (`chat/src/turn_context/state.rs`), but nothing emitted it. A tool that joined the deferred catalog produced only a host-side `run.warning` (`tool_deferred`); the model was never told.
   - Reachability works as designed when the host declares it. The deferred catalog does take late tools (`deferred_tools.rs` already covers that), and a session keeps the meta tools when a contributor declares `can_join_late`.
   - The ignored evaluation test used a contributor (`testkit::SwitchableContributor`) that switches its tool on mid-session without declaring `can_join_late`, and it expected the tool in the tools array. The context spec forbids that: "Tool became available: add it to the deferred catalog. Append a `tool_namespace_added` note. Never extend S1." So its expectation was stale, and its fixture misdeclared itself.
2. **OneMind contributors drop tools per turn.** This is OneMind's half; see the OneMind note (not reproduced there).

## What changed

- `rust/crates/chat/src/chat/prefix.rs`: when tools join the deferred catalog in a turn, `record` queues one `tool_namespace_added` turn note per namespace (the name's dotted prefix, or the whole name). The note says which tools are new and that they are reached with `tool_search` and `tool_call`. It is queued in the same transaction that persists the grown catalog, so a retried turn cannot announce twice. The turn context attaches it in the same turn, because `record` runs before `attach`. The frozen tools array and S2 do not change.
- `rust/crates/testkit/src/context_fixtures.rs`: `SwitchableContributor` declares `can_join_late`, which it does.
- `rust/api/agentkit-testkit.txt`: the public-API snapshot line for that method.
- `rust/crates/eval/tests/context.rs`: the ignored `a_restaged_tool_is_offered_after_its_contributor_turns_on` becomes `a_tool_that_joins_late_is_announced_and_reachable`, no longer ignored. It asserts that the late tool is announced and that every request carries the meta tools. This resolves the one "bug" ignore the handoff assigned to H2.1. The `extra_read` assertion that H0.2 removed from the `context_capture` example is covered by this test.

## Decisions I made

- I kept `can_join_late` as an opt-in instead of keeping the meta tools in every contributor-built session. A host whose contributors offer a stable set needs no meta tools when everything fits the direct budget. A host whose tools can appear later declares it, as OneMind's connected-server packs already do (`tools/pack_mcp.rs`). An undeclared late tool still gets the `tool_deferred` warning and now the announcement too, but without meta tools it cannot be called. If the owner prefers "always keep the meta tools for contributor sessions", it is a one-line change in `chat.rs` (`late`).
