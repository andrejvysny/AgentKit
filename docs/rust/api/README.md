# Public API freeze

The declaration reports freeze commit
`5a4bb61a479cc8ca3dfb0e24a8a0e1e0b37a9c61` (contract and umbrella version
`0.7.0`). They cover every published workspace package export and all sixteen
umbrella subpaths plus its root. The private native binding is an implementation
detail and is not the compatibility authority.

Reports are generated by the pinned Microsoft API Extractor from compiled
declarations, including reachable workspace types and inherited members from
classes that are not explicitly re-exported. Documentation diagnostics are
suppressed; exported signatures, overloads, and referenced types remain checked.
The baseline includes existing undocumented declarations and forgotten exports;
this gate does not certify documentation quality or runtime parity.
All 31 reports were independently regenerated from an archive of the frozen
commit and compared byte-for-byte with this working tree. Separate negative
drills prove that new exports and inherited-member changes fail the check.

```sh
bun run build
bun run build:umbrella
bun run check:api
```

CI compares reports without updating them. A deliberate reviewed API change can
regenerate reports with `bun run update:api`; regeneration must not be used to
hide migration incompatibilities. `--entry=core` restricts a local check to one
report. Normal checks never update the accepted reports. Native backend tests
and runtime qualification remain separate gates.
